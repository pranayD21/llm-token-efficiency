# Tooling audit and use ledger

All selected execution tools were available or installed and actually used. No paid account, external OAuth connection, or plugin installation was necessary. The project uses a local virtual environment, pinned distributions, binary wheels, and recorded artifact hashes. It does not execute downloaded research repository code.

## Installation record and security limits

The sandbox initially denied DNS. Approved read-only network access then exposed Python's missing certificate-chain configuration. System curl and pip with `/etc/ssl/cert.pem` succeeded; TLS verification was never disabled. `pip --only-binary=:all: --report ...` avoided source-build hooks. Dependencies are pinned after resolution and hashed from the installation report. Local setup can be reversed by removing the project `.venv`; no global packages were modified.

Installed transitive dependencies are in the lockfile. This audit checked provenance and installation integrity, not source-code correctness or all known vulnerabilities. No credential values were read or printed. A real-model experiment still requires an explicitly budgeted provider integration or an accessible local model runtime. This is an experimental limitation, not a blocker to the delivered local prototypes.

Final URL recheck: Consensus help/changelog and SciSpace help returned 403 to curl, though their content had been retrieved through the web tool. They are marked access-limited, and none was used for numerical research evidence. All included research records were accessible.
